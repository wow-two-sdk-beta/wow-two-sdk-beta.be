# WoW.Two.Sdk.Backend.Beta.Media.Captions

> Pure caption parsing across four formats — WebVTT, SubRip, TTML/DFXP, YouTube json3 — into ordered, cleaned segments. No network, no external dependencies.

Part of the `WoW2.Sdk.Backend.Beta` mono-lib (folder `src/Media/Captions/`).

## Usage

```csharp
using WoW.Two.Sdk.Backend.Beta.Media.Captions;
using WoW.Two.Sdk.Backend.Beta.Media.Captions.Parsers;

builder.Services.AddCaptionParsing();   // all parsers + facade + writers

public sealed class MyService(ICaptionParser captions)
{
    public IReadOnlyList<CaptionSegment> ParseSubRip(string srt)
        => captions.Parse(srt, CaptionFormat.SubRip);

    public IReadOnlyList<CaptionSegment> ParseDetected(string content)
        => captions.Parse(content);

    public CaptionTrack ParseEnglishTrack(string vtt)
        => captions.ParseTrack(vtt, "en", isAutoGenerated: true);
}
```

Need only one format? `AddVttCaptionParser()` still registers just the VTT parser.

## Types

Parser declarations live in `Parsers/` under the `Media.Captions.Parsers` namespace.
Registration extensions, caption data and writers remain in `Media.Captions`.

| Type | Role |
|---|---|
| `ICaptionParser` / `CompositeCaptionParser` | Format-aware facade — detect + dispatch; `Parse` / `TryParse` / `ParseTrack` |
| `IVttCaptionParser` · `ISrtCaptionParser` · `ITtmlCaptionParser` · `IJson3CaptionParser` | Per-format parsers (singleton, stateless) |
| `CaptionFormat` | `WebVtt` · `SubRip` · `Ttml` · `YouTubeJson3` |
| `CaptionFormatMapper` | `TryDetect(content, out format)` — sniffs the format from leading content |
| `ICaptionRenderer` / `VttCaptionRenderer` · `SrtCaptionRenderer` | Serialize segments back out — parse-then-write across formats = conversion |
| `CaptionSegment` | One timed line — `Start`, `End`, `Text`; an `ITimedText` |
| `ITimedText` | Any span of media text — implement it on a product's own segment type to reuse the helpers below |
| `TimedTextExtensions` | `Slice(start, end)` keeps overlapping spans · `ToParagraphs(options)` groups by pause and length |
| `TimedTextRenderer` · `TimedTextOptions` | `[m:ss] line` text, or paragraphs without timestamps |
| `CaptionClockMapper` | `ToClock(offset)` — `m:ss`, or `h:mm:ss` from the first hour |
| `CaptionTrack` | A language's track — `Language`, `IsAutoGenerated`, `Segments` |

## Behavior

- Null or blank input yields no segments. Accepted cues retain document order; cue order and start/end relationships are not validated.
- VTT and SRT strip tags and decode HTML entities. TTML flattens XML elements; json3 preserves text markup and entities.
- VTT consumes the header through the first blank line or timing line. Timing requires two-digit hours and three decimal digits.
- A VTT cue's text runs to the first empty line; a line holding only spaces (YouTube opens cues with one) is skipped, not an end.
- YouTube's rolling auto-captions — recognized by per-word timing tags — read line by line: each segment keeps only the lines its cue added, and the finished-line flashes between cues drop. 1:1 with json3's events on real tracks.
- Written VTT keeps one segment per cue and skips text-less cues and an identical cue repeated at the previous end. Matched but invalid timestamps throw `FormatException`; no partial list is returned.
- SRT skips blank-line-separated blocks without a matching timing line or text. Missing/out-of-order cue indices are tolerated; unparseable/overflowing conversions return zero, while clock-component ranges are not strictly validated.
- TTML invalid XML syntax returns no segments. Paragraphs without `begin` or text are skipped; missing `end`/`dur` makes end equal start.
- TTML unsupported/unparseable time tokens usually normalize to zero. Nonfinite/out-of-range offsets or duration arithmetic can throw without returning a partial list.
- json3 invalid JSON syntax returns no segments. Missing/non-array `events` yields none; events without required fields or text are skipped.
- json3 wrong JSON kinds can throw `InvalidOperationException`; out-of-range times can throw `OverflowException`. No partial list is returned on exceptions.
- Detection selects the first matching heuristic: `WEBVTT`, JSON-looking text containing `"events"`, XML-looking text containing `<tt`/`ttml`, comma timing, then any `-->` marker.
- JSON-looking or XML-looking text without its marker is unrecognized. Ambiguous content is not retried against other parsers.
- `TryParse` reports format recognition, not validity: `true` can accompany empty/partial segments, and leaf exceptions propagate.
- Explicit unknown `CaptionFormat` values yield no segments. `ParseTrack` rejects null/blank language tags.

## Conversion

```csharp
var segs = captions.Parse(json3, CaptionFormat.YouTubeJson3);
string srt = new SrtCaptionRenderer().Write(segs);   // json3 → SubRip
```

## Provenance

The VTT leaf was extracted from the TranscriptForge POC (`10x-ventures-transcript-forge`). SRT/TTML/json3 + the `ICaptionParser` facade + writers complete the caption *vector* (own logic, zero-dep) so the next transcript/subtitle consumer finds it whole. STT provider, audio extraction, and the transcript orchestrator remain product-inline until a second impl justifies the seams.
